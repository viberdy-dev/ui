# Black Border Form: AI prompt

Paste this into Cursor, Claude Code, v0, Lovable or Bolt to generate **Black Border Form** from scratch, or edit it first to restyle it. The finished code is [components/black-border-form.tsx](../components/black-border-form.tsx); the live demo is on [viberdy.dev](https://viberdy.dev/library/black-border-form?ref=github).

````text
Create neo-brutalist React + Tailwind form fields that press in when used and stamp their errors on: export BlackBorderField, BlackBorderCheck and BlackBorderForm (with their Props types and BlackBorderMessages).

Kit grammar: 3px ink borders set inline (no global border-colour rule can repaint them), square corners, hard shadows in the ink with no blur (5px on fields and the button, 3px on the checkbox), accent fills (yellow #ffd23f default, coral #ff6b6b, blue #74b9ff, lime #b4f462, pink #ff5fa2 or a regex-validated hex, names looked up by own key), motion 100ms linear on transform and translate (Tailwind v4 translate utilities set the translate property) and box-shadow, none under reduced motion. Type: labels in var(--font-display, "Archivo", "Archivo Black", "Arial Black", …) at 800, 15px; values in var(--font-sans, …) at 16px; hints and stamps in var(--font-mono, …) uppercase.

BlackBorderField { label, name, kind ("text" | "email" | "tel" | "url" | "textarea" | "select"), options (strings or { value, label }) and prompt (the disabled empty first option) for selects, hint, required, placeholder, autoComplete, minLength, maxLength, pattern, defaultValue, rows, disabled, error (a server error stamped until the value changes; a new error shows again), accent, ink, messages, className }: a label (with an aria-hidden "*" when required), then the control inside a white box with the 3px border and a 5px shadow; focus-within presses the box 5px onto its shadow (shadow none) and fills it with the accent (the fill in a class, not inline, so the focus class can win). Selects are appearance-none with a chevron drawn in 3px strokes. Emails cap maxLength at 254. Validation is the browser's own: onInvalid prevents the default bubble and stamps the error; blur stamps it if the field is not empty; change re-checks while a stamp shows. Map validity to short stamp text (valueMissing "Required" or "Pick one" for selects, typeMismatch "Needs an @ and a domain" for email, "Needs https://" for url, tooShort, tooLong, patternMismatch), overridable through messages. The stamp is a tilted (-2deg) black tag with white 11.5px mono caps, positioned over the box's top-right corner, inside an aria-live polite span referenced by aria-describedby, with NO transition; aria-invalid is set while a stamp shows.

BlackBorderCheck { label, name, value, required, defaultChecked, disabled, accent, ink, messages }: a real checkbox, appearance-none, 28px, 3px border, 3px shadow, checked fills with the accent and shows a check drawn in 3px strokes, focus-visible presses it 3px in; required stamps "Tick this to continue".

BlackBorderForm { children, onSubmit(formData) that may return a promise, submitLabel, busyLabel, doneLabel, doneNote, failLabel, accent, ink, action, className }: a form with method="post" (so without JavaScript nothing typed lands in the address bar) whose action is sanitised (strip tabs and newlines, refuse backslashes, allow https and same-site paths starting / or ? but not //; drop anything else). On the first invalid event of a submit attempt (every invalid event fires in the same task; reset the flag with a setTimeout 0, not a microtask, which runs between listeners) focus that field. On a valid submit, prevent the default, read FormData, set busy (the button keeps its shadow, shows the busy label, sets aria-busy and aria-disabled, and further submits are ignored), await onSubmit, and take a run number so a stale result cannot win. On success, a "received" stamp (the accent, 3px border, 8px shadow, rotated -4deg, 44px display caps and a mono note) lands over the form on a 72% white veil, takes focus (tabIndex -1, role status), and the fields are disabled through a fieldset so Tab cannot reach them behind it. On failure, a stamped retry line appears beside the button in a role="status" paragraph. The submit button has the kit's press: hover lifts 2px onto a 7px shadow, pointer down or Enter or Space lands it on its shadow.

Write the focus-ring declarations as important utilities (for example focus-visible:![outline-style:dashed], focus-visible:![outline-offset:4px], focus-visible:![border-radius:0]) and keep the ring colour inline, so an unlayered global :focus-visible rule in the host app cannot replace them.

Output one self-contained "use client" TSX file with no dependencies beyond React. Build strings with + rather than template literals.
````
